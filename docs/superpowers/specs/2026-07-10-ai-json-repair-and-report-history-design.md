# AI 截图分析容错与自然周日报历史设计

## 背景

当前截图 AI 请求成功后，MiniMax 和 OpenAI-compatible Provider 都会使用严格
`JSON.parse` 解析模型响应。模型只要返回未转义双引号、异常换行、缺失逗号或
Markdown 代码块，就会导致截图分析失败，并把原生 JSON 解析错误显示给用户。

报告页当前只调用 `dashboard.getToday()`，因此左侧日报列表永远只有今天。后端虽然
提供历史概览，但没有返回日报正文，报告页也没有调用该接口。

## 目标

1. 自动修复模型返回的常见轻微 JSON 格式错误，尽量保留截图分析结果。
2. 无法修复时显示明确的中文提示，不暴露原生 `JSON.parse` 错误。
3. 报告页展示当前自然周周一到今天的日报，历史日报可以点击查看。
4. 历史日报只读，避免通过现有“保存今日日报”接口误覆盖今天的数据。

## AI 响应解析

新增共享的截图分析响应解析器，MiniMax 和 OpenAI-compatible Provider 均调用该解析器。

解析顺序：

1. 去除首尾空白、Markdown JSON 代码块和 JSON 前后的解释文字。
2. 先执行标准 `JSON.parse`。
3. 标准解析失败时，使用 `jsonrepair` 修复常见格式错误后再次解析。
4. 校验 `title`、`summary`、`category` 为非空字符串，`confidence` 为有限数字。
5. 无法修复或字段不可用时，抛出统一中文错误：
   `截图 AI 返回内容格式异常，自动修复失败，请稍后重试。`

原始模型响应不写入数据库或日志。截图提示词补充严格 JSON、字符串双引号转义和禁止
额外说明的要求，以减少修复器介入次数。

## 自然周日报历史

复用现有 `dashboard.getHistory()` IPC，不新增重复通道。默认查询范围调整为当前自然周：
周一到今天，不返回未来日期。

历史数据为每一天返回：

- 日期。
- 记录时长。
- 事件数量。
- 日报状态。
- 已保存的 `daily` 类型日报正文；没有已保存日报时为 `null`。

查询日报时使用 `getByDateAndType(date, "daily")`，避免未来与周报类型混淆。

报告页同时加载今天状态和自然周历史：

- 今天始终显示，并继续承载当前草稿和保存操作。
- 周一到昨天只展示已保存日报，不展示空白占位日期。
- 点击历史日报后在编辑区显示正文，并切换为只读。
- 查看历史日报时禁用保存按钮，复制功能仍可使用。
- 点击今天后恢复今天草稿和保存能力。
- 自动刷新不得把用户正在查看的历史日报强制切回今天。

## 测试

先添加失败测试，再实现代码：

1. 共享解析器可处理 Markdown 代码块、前后解释文字、未转义双引号和异常换行。
2. 两种 Provider 都使用共享解析行为。
3. 完全不可修复或字段缺失时返回统一中文错误。
4. 历史默认范围是当前自然周周一到今天。
5. 历史只读取 `daily` 类型日报并返回正文。
6. 报告页视图模型合并今天草稿与本周已保存日报，历史项为只读。
7. 运行定向单元测试、全部单元测试、类型检查和生产构建。

## 非目标

- 不保存 AI 原始响应。
- 不自动二次请求 AI。
- 不提供跨周翻页或日期筛选。
- 不允许编辑历史日报。
- 不改变周报生成和保存逻辑。
