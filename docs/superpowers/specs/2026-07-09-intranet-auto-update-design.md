# 内网自动更新设计

## 目标

为日报助手增加应用内“检查更新”能力。用户点击按钮后，应用通过内网 HTTP/HTTPS 发布目录检查是否存在新版；发现新版本后由应用自动下载，下载完成后提示用户立即重启安装。本次发布版本号为 `0.1.1`。

## 用户体验

- 设置页增加“应用更新”区域。
- 显示当前版本号，例如 `0.1.1`。
- 更新地址固定为 `http://192.168.19.220/daily-assistant/releases/`，用户界面不提供地址配置项。
- “检查更新”按钮通过环境变量控制显示与隐藏；默认隐藏，显式开启后显示。
- 点击“检查更新”后，按钮进入检查中状态，页面显示明确反馈。
- 如果没有新版本，显示“当前已是最新版本”。
- 如果发现新版本，自动开始下载并显示下载进度。
- 下载完成后显示“新版本已下载，重启后安装”，并提供“立即重启安装”按钮。
- 如果网络不可达、更新文件缺失或版本元数据异常，显示可操作的中文错误提示。

## 更新源

更新源采用 `electron-updater` 的 generic HTTP/HTTPS 发布方式。内网服务器只需要提供静态文件，不需要后端接口。

固定发布目录：

`http://192.168.19.220/daily-assistant/releases/`

发布目录包含：

- `latest.yml`
- `日报助手 Setup <version>.exe`
- `日报助手 Setup <version>.exe.blockmap`

发布新版本时，需要先把 `package.json` 的 `version` 提升到目标版本，再执行 Windows 打包命令。打包配置需要生成 `latest.yml`，并让应用能读取 generic 更新源。

## 架构

主进程负责所有更新逻辑，渲染进程只负责展示和触发操作。

- 新增主进程更新服务，封装 `electron-updater`。
- 新增 update IPC 通道：检查更新、开始下载状态推送、退出并安装。
- preload 通过 `window.dailyAssistant.updater` 暴露窄接口。
- 设置页调用 updater IPC，并订阅更新状态。
- 更新源地址在主进程更新服务中集中定义为固定常量。
- 渲染层根据环境变量决定是否渲染“应用更新”区域；未开启时用户看不到检查更新入口。

## 环境变量开关

检查更新入口使用 `VITE_ENABLE_APP_UPDATE` 控制：

- `VITE_ENABLE_APP_UPDATE=true`：显示“应用更新”区域和“检查更新”按钮。
- 其他值或未设置：隐藏“应用更新”区域。

该变量只控制界面入口是否显示。主进程仍保留更新 IPC 的开发环境保护和打包环境检查，避免开发环境误触发真实安装流程。

## 数据流

1. 构建时设置 `VITE_ENABLE_APP_UPDATE=true`，设置页显示“应用更新”区域。
2. 用户点击“检查更新”。
3. 渲染进程调用 `updater:check`.
4. 主进程使用固定更新地址调用 `autoUpdater.setFeedURL`.
5. 主进程执行检查更新。
6. 检查结果、下载进度、下载完成或错误状态通过事件推送给渲染进程。
7. 用户点击“立即重启安装”后，主进程调用 `quitAndInstall`.

## 错误处理

- 访问失败：提示检查内网地址、服务器、防火墙或 VPN。
- 找不到 `latest.yml`：提示发布目录缺少更新元数据。
- 没有新版本：提示当前版本已是最新。
- 下载失败：保留当前应用运行状态，允许用户再次检查更新。
- 开发环境点击更新：提示自动更新仅在打包后的应用中可用。

## 安全与限制

- 更新只从固定内网 HTTP 地址获取。
- 不在渲染进程直接下载或执行安装包。
- 不自动静默重启，下载完成后由用户确认安装。
- 不在本次实现代码签名；若后续企业分发要求更高可信度，应补充签名证书流程。
- 不支持共享目录 `\\server\path` 直接更新；如需共享目录，需要先通过内网 HTTP 服务暴露。

## 测试策略

- 单元测试：固定更新源常量、环境变量显示开关、更新状态文案、设置页更新区域渲染。
- IPC 契约测试：preload 暴露 updater API，主进程注册 updater 通道。
- 构建验证：`npm run build`。
- 打包验证：`npm run dist:win -- --publish never` 或等价命令，确认生成 `latest.yml`、安装包和 blockmap。
- 手动 QA：用本机静态 HTTP 服务模拟内网发布目录，验证检查、下载进度和下载完成提示。

## 发布流程

1. 将 `package.json` 版本提升为 `0.1.1`。
2. 构建并打包 Windows NSIS 安装包。
3. 将 `release` 中的 `latest.yml`、安装包和 blockmap 上传到 `http://192.168.19.220/daily-assistant/releases/` 对应的服务器目录。
4. 已安装旧版本的用户在设置页点击“检查更新”。
5. 应用自动下载 `0.1.1` 并提示重启安装。
